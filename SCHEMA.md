# SAT EQB Output Schema

This document defines the persisted schema for data/history generated by this project.

Schema version markers:
- Run artifacts: `schema_version`
- Profile state: `state_version`
- TODO index: `index_version`
- Run progress checkpoints: `progress_version`

Current versions:
- `schema_version`: `1.0.0`
- `state_version`: `1.0.0`
- `index_version`: `1.0.0`
- `progress_version`: `1.0.0`

## Root Layout
All generated files are written under:
- `$OUT_DIR/sat_eqb`

Directory structure:
- `dataset/questions/`:
  - stable per-question content directories (JSON/HTML/assets)
- `dataset.jsonl`:
  - canonical consolidated dataset snapshot updated after each run
- `runs/<run_id>/`:
  - run-level logs and statistics
- `state/profiles/<profile_id>.json`:
  - resumable state per filter profile
- `state/latest-run.json`:
  - pointer to latest completed/interrupted/failed run
- `history.jsonl`:
  - append-only run history summary records
- `todo/`:
  - global anomaly/TODO backlog and structured index

Compatibility:
- Legacy `data/questions/` content from older versions is automatically migrated to `dataset/questions/` on subsequent runs.

## `dataset/questions/<question_dir>/question.json`
Type: JSON object

Top-level fields:
- `metadata` object:
  - `question_id` string
  - `assessment` string
  - `assessment_id` integer
  - `test` string
  - `test_id` integer
  - `domain` string
  - `domain_code` string
  - `skill` string
  - `skill_code` string
  - `difficulty` string
  - `score_band_range` integer or null
  - `external_id` string or null
  - `ibn` string or null
  - `program` string or null
  - `create_date` integer epoch-ms or null
  - `update_date` integer epoch-ms or null
  - `state_standards` array of strings
- `source` string:
  - `digital` or `legacy`
- `content` object:
  - `prompt_html` string
  - `stem_html` string
  - `answer_options` array of objects:
    - `letter` string
    - `content_html` string
  - `rationale_html` string
  - `correct_answers` array of strings
  - `question_type` string or null
- `assets` array of objects:
  - `original_url` string
  - `local_path` string (relative path under question dir)
  - `source_type` string (`remote` or `data_uri`)
  - `mime_type` string or null
  - `size_bytes` integer or null
  - `sha256` string or null
- `parse_warnings` array of strings
- `raw_table_row` object:
  - complete raw row from `digital/get-questions`
- `raw_detail_payload` object:
  - complete raw detail payload from source endpoint
- `raw_payload` object:
  - backward-compatible alias of `raw_detail_payload`
- `lifecycle` object:
  - `created_run_id` string
  - `modified_run_id` string
  - `create_time` ISO8601 string
  - `modified_time` ISO8601 string

## `dataset/questions/<question_dir>/question.html`
Type: HTML document

Contains:
- metadata table
- prompt/stem/answers/rationale HTML
- optional parse warning section
- links rewritten to local `assets/` paths where applicable

## `runs/<run_id>/run-config.json`
Type: JSON object

Fields:
- `schema_version` string
- `run_id` string
- `run_label` string or null
- `profile_id` string
- `started_at_utc` ISO8601 string
- `root_dir` string
- `filters` object (profile filters)
- `flags` object:
  - `restart` boolean
  - `download_new` boolean
  - `download_failed` boolean
  - `save_output` boolean
  - `download_assets` boolean
  - `continue_on_error` boolean
  - `include_state_standards` boolean
- `amount` integer or string (`all` value is normalized before storage)
- `rate_limit` object:
  - `max_requests_per_second` number
  - `min_request_interval_seconds` number

## `runs/<run_id>/run-summary.json`
Type: JSON object

High-level run result:
- `schema_version` string
- `run_id` string
- `run_label` string or null
- `profile_id` string
- `status` string:
  - `completed`, `completed_with_errors`, `interrupted`, or `failed`
- `started_at_utc` ISO8601 string
- `finished_at_utc` ISO8601 string
- `duration_seconds` number
- `root_dir` string
- `run_dir` string
- `run_progress_path` string
- `dataset_path` string
- `profile_state_path` string
- `selection` object
- `processing` object
- `requests` object
- `sources` object
- `assets` object
- `dataset` object:
  - `new_count` integer
  - `modified_count` integer
  - `unchanged_count` integer
  - `total_records_after_run` integer
- `parsing` object
- `todo` object:
  - `total_items` integer
  - `new_signatures` integer
  - `unique_signatures_in_run` integer
  - `global_open_signatures` integer
  - `by_category` object (`category` -> count)
  - `by_severity` object (`severity` -> count)
  - `run_todo_items_path` string
  - `todo_items_path` string
  - `todo_index_path` string
  - `todo_markdown_path` string
  - `top_signatures` array
- `errors_count` integer
- `errors` array of strings
- `flags` object
- `filters` object
- `run_artifacts` object:
  - `stats_yaml_path` string
  - `todo_items_markdown_path` string
  - `new_ids_csv_path` string
  - `modified_ids_csv_path` string
  - `todo_items_jsonl_path` string
  - `todo_summary_json_path` string

## `runs/<run_id>/run-stats.json`
Type: JSON object

Detailed stats blocks:
- `run` object
- `timing` object
- `selection` object
- `processing` object
- `sources` object
- `assets` object
- `dataset` object:
  - `new_count` integer
  - `modified_count` integer
  - `unchanged_count` integer
  - `total_records_after_run` integer
- `parsing` object
- `todo` object:
  - run-level TODO counters by category/severity
- `progress` object:
  - `checkpoints_written` integer
- `requests` object:
  - includes per-endpoint counts, status code counts, and throttling sleep seconds

## `runs/<run_id>/stats.yaml`
Type: YAML document

YAML convenience view for run diagnostics:
- `run_summary` object (same content as `run-summary.json`)
- `run_stats` object (same content as `run-stats.json`)

## `runs/<run_id>/run-progress.json`
Type: JSON object

Frequent checkpoint file for crash-safe resumability visibility:
- `schema_version` string
- `progress_version` string
- `run_id` string
- `profile_id` string
- `stage` string:
  - `initialized`, `selected`, `processing`, `interrupted`, `completed`, `completed_with_errors`, or `failed`
- `updated_at_utc` string
- `selection` object
- `processing` object
- `dataset` object:
  - `new_count` integer
  - `modified_count` integer
  - `unchanged_count` integer
  - `total_records_after_run` integer
- `todo` object:
  - `total_items` integer
  - `unique_signatures_in_run` integer
- `current` object:
  - `question_key` string or null
  - `question_id` string or null
  - `position` integer or null
  - `total_candidates` integer or null

## `runs/<run_id>/errors.jsonl`
Type: JSON Lines

One line per question-level failure for this run:
- `timestamp_utc` string
- `question_key` string
- `question_id` string
- `error` string
- `traceback` string

## `runs/<run_id>/todo-items.jsonl`
Type: JSON Lines

Per-run anomaly/TODO events:
- `schema_version` string
- `timestamp_utc` string
- `run_id` string
- `profile_id` string
- `signature` string
- `category` string
- `severity` string
- `summary` string
- `question_key` string or null
- `question_id` string or null
- `source` string or null
- `details` object
- `recommended_action` string

## `runs/<run_id>/todo-summary.json`
Type: JSON object

Per-run TODO summary:
- `schema_version` string
- `run_id` string
- `profile_id` string
- `total_items` integer
- `new_signatures` integer
- `unique_signatures_in_run` integer
- `global_open_signatures` integer
- `by_category` object
- `by_severity` object
- `run_todo_items_path` string
- `todo_items_path` string
- `todo_index_path` string
- `todo_markdown_path` string
- `top_signatures` array

## `runs/<run_id>/todo-items.md`
Type: Markdown

Run-level human-readable TODO report:
- summary counts
- dataset change highlights (new/modified IDs)
- top anomaly signatures
- run errors
- links to TODO artifacts

## `runs/<run_id>/new_ids.csv`
Type: CSV

Columns:
- `question_key`
- `question_id`
- `external_id`
- `ibn`

Contains question IDs created in this run.

## `runs/<run_id>/modified_ids.csv`
Type: CSV

Columns:
- `question_key`
- `question_id`
- `external_id`
- `ibn`

Contains existing questions whose persisted dataset payload changed in this run.

## `runs/<run_id>/run.log`
Type: plain text log

Contains run-level operational logging:
- progress messages
- parse warnings
- endpoint/reliability diagnostics
- exception stacks

## `state/profiles/<profile_id>.json`
Type: JSON object

Persistent resumable state per filter profile:
- `state_version` string
- `profile_id` string
- `filters` object
- `created_at_utc` ISO8601 string
- `updated_at_utc` ISO8601 string
- `questions` object (map by `question_key`):
  - `question_id` string
  - `external_id` string or null
  - `ibn` string or null
  - `status` string (`success` or `failed`)
  - `attempt_count` integer
  - `success_count` integer
  - `failure_count` integer
  - `last_run_id` string
  - `last_attempt_at_utc` string
  - `last_success_at_utc` string (success entries)
  - `last_failure_at_utc` string (failed entries)
  - `last_error` string or null
  - `data_path` string (success entries)

## `state/latest-run.json`
Type: JSON object

Pointer to most recent run:
- `schema_version` string
- `run_id` string
- `profile_id` string
- `status` string
- `finished_at_utc` string
- `run_dir` string
- `todo_items` integer

## `history.jsonl`
Type: JSON Lines

Append-only run history summary entries:
- `schema_version` string
- `run_id` string
- `run_label` string or null
- `profile_id` string
- `status` string
- `started_at_utc` string
- `finished_at_utc` string
- `duration_seconds` number
- `selection` object
- `processing` object
- `dataset` object:
  - `new_count` integer
  - `modified_count` integer
- `todo` object:
  - `total_items` integer
  - `unique_signatures_in_run` integer
- `errors_count` integer
- `run_dir` string

## `dataset.jsonl`
Type: JSON Lines

Canonical main dataset snapshot. One JSON object per question keyed by embedded `question_key`:
- includes all fields from `dataset/questions/<question_dir>/question.json`
- includes top-level `question_key` string for fast indexing
- includes `lifecycle` tags for creation/modification lineage

## `todo/todo-index.json`
Type: JSON object

Deduplicated global TODO index:
- `index_version` string
- `created_at_utc` string
- `updated_at_utc` string
- `items` object (`signature` -> item object):
  - `signature` string
  - `category` string
  - `severity` string
  - `summary` string
  - `details` object
  - `recommended_action` string
  - `status` string (`open`)
  - `first_seen_at_utc` string
  - `last_seen_at_utc` string
  - `updated_at_utc` string
  - `occurrences` integer
  - `sample_run_ids` array of strings
  - `sample_question_keys` array of strings
  - `sample_question_ids` array of strings

## `todo/todo-items.jsonl`
Type: JSON Lines

Append-only global TODO event stream.
Each line matches `runs/<run_id>/todo-items.jsonl` entry schema.

## `todo/TODO.md`
Type: Markdown

Human-readable prioritized backlog generated from `todo-index.json`.
